# uiux-skills — AI 编程助手的 UI/UX 技能集

> 让 AI 写出的代码不仅能跑，还要好用。

[English](README.md) | **中文**

uiux-skills 是一套 AI 编程助手技能集，将 UI/UX 专业知识注入到 AI 编程（vibe coding）的工作流中。它不是在代码写完后检查设计问题，而是在 AI 写出第一行前端代码之前，就让它理解你的产品、你的用户和你的体验标准。

---

## 痛点

你让 AI「建一个登录页」，它生成的代码能编译通过，但是：

- 表单标签在你开始输入时消失了
- 点击提交按钮后没有任何加载状态
- 错误提示 3 秒后自动消失
- 看起来和所有 AI 生成的页面一模一样（紫色渐变背景 + 卡片墙）

**90% 的 AI 生成 UI 都有同样的体验问题。** 不是因为 AI 做不了更好，而是没人告诉它，对于 *你的* 产品和 *你的* 用户，「更好」意味着什么。

---

## 工作原理

uiux-skills 是一个 5 步管线，每一步都基于前一步的结果：

```
/uiux profile   → 分析项目，识别产品类型和上下文
/uiux insight   → 生成用户画像，映射关键用户旅程
/uiux generate  → 生成定制化的 UX-RULES.md 规则文件
/uiux review    → 对照规则审核代码，发现违规并给出修复方案
/uiux improve   → 提出体验改进建议和产品发展方向
```

完成第 3 步后，一个 `UX-RULES.md` 文件会生成在项目根目录。所有能读取项目上下文的 AI 工具（Claude Code、Cursor、Windsurf 等）在生成代码时都会自动遵循这些规则。

## 快速开始

### Claude Code

```bash
# 作为技能添加
claude skill add /path/to/uiux-skills

# 或者先克隆再添加
git clone https://github.com/DietCokewithSugar/uiux-skills.git
claude skill add ./uiux-skills
```

### 其他 AI 编程工具（Cursor、Windsurf、Codex 等）

将 `SKILL.md` 文件和 `frameworks/`、`patterns/`、`anti-patterns/` 目录复制到你的 AI 工具的技能/规则目录中。SKILL.md 的格式兼容 Cursor、Codex、OpenClaw 以及所有支持通用技能格式的工具。

### 手动方式（任何项目）

只需运行第 1–3 步生成 `UX-RULES.md`，然后将其放入项目根目录。任何能读取项目文件的 AI 工具都会自动识别并遵循这些规则。

## 评估框架

uiux-skills 会根据你的产品类型自动选择最合适的评估框架：

| 产品类型 | 评估框架 | 侧重点 |
|---|---|---|
| SaaS / 企业工具 | ETS（体验信任评分） | 信任、效率、错误预防 |
| 消费者应用 / 电商 | HEART（Google 框架） | 满意度、参与度、留存 |
| MVP / 原型 | SUS-Lite（系统可用性量表） | 快速可用性基线 |
| 内容平台 / 创意工具 | UEQ-Lite（用户体验问卷） | 吸引力、刺激性 |

你也可以手动指定框架，或同时使用多个框架进行综合评估。

### ETS — 体验信任评分（Experience Trust Score）

> 适用于企业工具、内部平台、管理后台等以信任和效率为核心的产品。

**5 个评估维度：**

| 维度 | 权重 | 关注点 |
|---|---|---|
| 任务效率 | 0.25 | 用户能否快速、无冗余步骤地完成核心任务 |
| 错误预防与恢复 | 0.25 | 系统是否防止误操作、帮助用户优雅恢复 |
| 系统透明度 | 0.20 | 用户是否始终知道发生了什么、为什么 |
| 一致性与可预测性 | 0.15 | 系统在类似场景下表现是否一致 |
| 感知可靠性 | 0.15 | 系统是否给人稳定、专业的感觉 |

**评分标准：** 90–100 优秀（用户完全信赖）| 70–89 良好 | 50–69 一般 | <50 差（用户寻找替代品）

### HEART — Google 用户体验度量框架

> 适用于消费者应用、电商、社交产品等关注增长指标的产品。

**5 个评估维度：**

| 维度 | 权重 | 关注点 |
|---|---|---|
| 满意度（Happiness） | 0.20 | 用户是否感到满意和愉悦 |
| 参与度（Engagement） | 0.20 | 用户与产品的互动深度 |
| 采纳率（Adoption） | 0.20 | 新用户是否成功完成引导 |
| 留存率（Retention） | 0.20 | 用户是否持续回来使用 |
| 任务成功率（Task Success） | 0.20 | 用户能否完成想做的事 |

**评分标准：** 90–100 卓越体验 | 70–89 良好 | 50–69 能用但不出彩 | <50 严重影响业务指标

### SUS-Lite — 轻量级系统可用性量表

> 适用于 MVP、原型、黑客马拉松项目等需要快速评估可用性的场景。

**5 个评估维度：**

| 维度 | 权重 | 关注点 |
|---|---|---|
| 可学习性 | 0.30 | 新用户无需说明即可使用 |
| 效率 | 0.25 | 核心任务 5 次点击 / 30 秒内完成 |
| 可记忆性 | 0.15 | 两周后回来仍然知道怎么用 |
| 容错性 | 0.20 | 用户犯错后系统如何处理 |
| 满意度 | 0.10 | 用户不会抱怨这个工具 |

**评分标准：** 80–100 可以发布 | 60–79 有已知摩擦点 | 40–59 需要改进 | <40 不要发布

### UEQ-Lite — 轻量级用户体验问卷

> 适用于内容平台、创意工具、作品集网站等以「感觉」和「体验」取胜的产品。

**6 个评估维度：**

| 维度 | 权重 | 关注点 |
|---|---|---|
| 吸引力 | 0.20 | 产品整体观感是否吸引人 |
| 清晰度 | 0.20 | 产品是否容易理解和学习 |
| 效率 | 0.20 | 用户能否不费力地达成目标 |
| 可靠感 | 0.15 | 用户是否感到可控和安全 |
| 刺激性 | 0.15 | 产品是否令人兴奋、有动力使用 |
| 新颖性 | 0.10 | 产品是否有创新感 |

**评分标准：** 80–100 优秀 | 60–79 良好 | 40–59 中性 | <40 负面印象

## 详细使用指南

### 第 1 步：产品画像（`/uiux profile`）

**目标：** 在做任何 UX 决策之前，先理解你在构建什么。

**信息来源（按优先级排序）：**
1. `README.md` — 项目描述和目标
2. `package.json` / `Cargo.toml` / `pyproject.toml` — 依赖和技术栈
3. 文件树结构 — `src/pages/`、`src/components/`、路由文件
4. 现有设计文档、PRD、`.cursor/rules` 或 `CLAUDE.md`
5. 如果以上都没有，会询问你用 2–3 句话描述项目

**输出格式：**

```
产品类型：    [SaaS 管理后台 | 移动应用 | 电商 | 落地页 | 内部工具 | 内容平台 | 社交应用 | 开发者工具 | ...]
行业/领域：   [医疗 | 金融科技 | 教育 | 零售 | 效率工具 | ...]
核心功能：    [一句话：这个产品为用户做什么？]
技术栈：     [React/Vue/Svelte + 检测到的相关库]
平台：       [Web | 移动 Web | 原生移动 | 桌面 | 响应式]
成熟度：     [原型 | MVP | 增长期 | 成熟期]
```

---

### 第 2 步：用户洞察（`/uiux insight`）

**目标：** 理解谁会使用你的产品，以及他们在意什么。

**输出内容包括：**

#### 用户画像（2–3 个主要角色）

每个画像包含：
- 姓名（虚构但便于记忆）+ 角色
- 年龄范围 & 技术熟练度
- 使用产品的主要目标
- 关键痛点/挫折感
- 使用场景（设备、环境、时间压力、情绪状态）

**示例输出：**

```markdown
## 用户画像

### 画像 1：张莉 — 诊所前台
- **基本信息：** 28 岁，技术熟练度中等
- **目标：** 快速为患者安排预约，减少电话等待时间
- **痛点：** 当前系统操作繁琐，每次预约需要 8 次点击
- **场景：** 台式电脑，工作日全天使用，经常被打断
```

#### 关键用户旅程（3–5 条）

- 入口 → 关键操作 → 成功状态
- 用户最可能在哪里流失
- 情感高峰在哪里（如付款、提交数据、遇到错误）

#### 特殊考量

- 无障碍需求（视觉、运动、认知）
- 国际化需求
- 网络限制（离线、慢网）
- 设备限制（小屏幕、仅触屏、键盘优先）

---

### 第 3 步：生成 UX 规则（`/uiux generate`）

**目标：** 生成项目专属的 `UX-RULES.md` 文件，让 AI 编程助手自动遵循。

**框架自动选择逻辑：**

| 产品类型 | 推荐框架 | 原因 |
|---|---|---|
| 商业产品（SaaS、电商） | HEART | 度量满意度、参与度、采纳、留存、任务成功 |
| 企业/内部工具 | ETS | 关注可靠性、效率、信任 |
| 早期/MVP | SUS-Lite | 快速可用性评估，轻量 |
| 内容/媒体产品 | UEQ-Lite | 捕捉吸引力、清晰度、效率 |
| 高风险领域（医疗、金融） | ETS + 自定义安全规则 | 信任和错误预防至关重要 |

**规则分为 6 个类别，每条规则标注优先级：**

| 类别 | 包含内容 |
|---|---|
| 交互规则 | 表单、导航、反馈、加载状态、错误处理 |
| 视觉规则 | 布局、排版、间距、颜色、对比度、层级 |
| 内容规则 | 微文案、标签、错误消息、空状态、引导文案 |
| 无障碍规则 | WCAG 合规、屏幕阅读器、键盘导航、触摸目标、色盲适配 |
| 性能规则 | 加载时间、骨架屏、乐观更新、离线行为 |
| 领域特定规则 | 行业特有规则（如医疗的 HIPAA、支付的 PCI） |

**优先级标注：**
- `MUST`（必须）— 违反即为体验事故
- `SHOULD`（应该）— 强烈推荐
- `MAY`（可选）— 锦上添花

**输出示例：**

```markdown
# UX Rules — 牙科预约系统

> Generated by uiux-skills
> Product: 医疗 SaaS | Framework: ETS | Generated: 2026-04-10

## 交互规则

### [MUST] 预约确认必须显示完整信息
预约确认页面必须清晰显示日期、时间、医生姓名和诊室。
理由：医疗预约出错的代价很高，患者需要确认无误。

### [SHOULD] 表单支持多种输入格式
手机号输入应接受多种格式（带横线、空格或纯数字）。
理由：减少输入摩擦，降低表单放弃率。
```

---

### 第 4 步：审核代码（`/uiux review`）

**目标：** 对照 UX 规则审核已有代码或组件。

**审核流程：**
1. 读取代码，理解生成的 UI
2. 对照 `UX-RULES.md` 中的每条适用规则进行检查
3. 为每个违规项输出报告

**严重级别：**

| 级别 | 含义 | 行动 |
|---|---|---|
| 🔴 **严重（CRITICAL）** | 体验崩溃，用户会失败或离开 | 立即修复 |
| 🟡 **警告（WARNING）** | 体验降级，用户会感到困难 | 发布前修复 |
| 🔵 **信息（INFO）** | 非最优，用户不会立刻注意到 | 值得改进 |

**输出格式：**

```markdown
### 🔴 严重 — 违反规则：占位符代替标签

**位置：** LoginForm.tsx:15
**问题：** 输入框仅使用 placeholder 作为标签，输入时标签消失
**影响：** 用户输入到一半会忘记这个字段要填什么
**修复：** 在每个输入框上方添加 <label> 元素

### 🟡 警告 — 违反规则：缺少提交加载状态

**位置：** LoginForm.tsx:42
**问题：** 提交按钮在 API 调用期间保持静态
**修复：** 添加 disabled 状态 + 旋转加载图标

---
UX 审核评分：4/10
严重：2 | 警告：1 | 信息：1
最优先修复：为所有表单输入添加可见标签
```

---

### 第 5 步：改进建议（`/uiux improve`）

**目标：** 超越修复违规——提出改进建议和产品发展方向。

**输出包含 4 个板块：**

#### 🎯 快速改进（低成本、高回报）

立即可以执行的改进，例如：
- 为结账流程添加步骤指示器（第 1/3 步、2/3 步…）
- 在结账页面右侧固定显示订单摘要
- 自动保存购物车内容

#### ✨ 体验差异化（让你的产品脱颖而出）

与竞品拉开差距的 UX 方案，例如：
- 游客结账 + 购买后可选创建账户
- 购物车中的「稍后再买」功能
- 支付区域附近展示信任标志

#### 📈 增长导向 UX（服务业务目标）

支持留存、转化、参与等增长指标的 UX 模式，例如：
- 退出时提示已保存的购物车
- 智能地址自动补全减少表单摩擦
- 一键复购

#### 🧭 战略方向（下一步该投入哪里）

```markdown
1. 将结账简化为最多 2 步（地址 → 支付+确认）
2. 在商品页面添加实时运费估算
3. 实现愿望清单功能促进长期参与
```

---

### 什么时候用哪个步骤？

| 场景 | 操作 |
|---|---|
| 新项目，从零开始 | 运行第 1–3 步生成 UX-RULES.md，然后在第一个组件上运行第 4 步 |
| 已有项目，没有 UX-RULES.md | 先运行第 1–3 步 |
| 已有项目，已有 UX-RULES.md | 直接运行第 4 步（审核）或第 5 步（改进） |
| 「帮我把这个做好看点」 | 运行第 5 步 |
| 「检查一下我的表单/页面/组件」 | 运行第 4 步 |

## 使用示例

### 示例 1：新项目设置

**你说：** 我在做一个 React 项目，是一个牙科诊所的在线预约系统。

**uiux 执行：**
1. `/uiux profile` → 识别为：医疗 SaaS，预约系统，响应式 Web
2. `/uiux insight` → 生成画像（焦虑的患者、忙碌的前台、诊所管理员），映射预约旅程
3. `/uiux generate` → 选择 ETS 框架（医疗领域信任至关重要）+ 自定义安全规则，生成 `UX-RULES.md`

**结果：** 在写第一个组件之前，项目已经有了 `UX-RULES.md` 确保：
- 预约确认页清晰显示日期/时间/医生
- 取消预约需要明确确认但操作路径清晰
- 患者信息表单容错性强（接受多种手机号格式）
- 预约过程中的加载状态防止重复提交
- 无障碍符合 WCAG AA 标准（医疗领域要求）

---

### 示例 2：审核已有组件

**你说：** `/uiux review`（贴入一个登录表单组件）

**uiux 发现：**

```
🔴 严重 — 占位符代替标签
   输入框用 placeholder 作为标签。输入时消失。
   修复：在每个 input 上方添加 <label> 元素。

🔴 严重 — 没有错误提示
   登录失败只显示红色边框，没有文字说明。
   修复：添加内联错误：「邮箱或密码不正确，请重试。」

🟡 警告 — 提交无加载状态
   提交期间按钮保持静态。
   修复：添加 disabled 状态 + 旋转图标。

🔵 信息 — 密码框没有显示/隐藏切换
   用户无法查看输入的密码。
   修复：添加显示/隐藏密码的切换图标。

UX 审核评分：4/10
最优先修复：为所有表单输入添加可见标签
```

### 示例 4：已有项目，没有 UX-RULES.md

**你说：** 帮我检查一下项目的 UX 质量。（项目已有代码但没有 UX-RULES.md）

**uiux 自动执行：**

## 常见 AI UX 反模式速查

以下是 AI 编程工具最常犯的 UX 错误，uiux-skills 会在审核中自动标记：

| 反模式 | 问题 | 修复方案 |
|---|---|---|
| 🟣 紫色渐变综合症 | 所有页面都用同一个 `#667eea → #764ba2` 渐变背景 | 使用纯色、微妙纹理或品牌配色 |
| 🧱 卡片墙 | 所有内容都是网格卡片，没有视觉层级 | 建立层级：英雄区、主要内容、次要内容 |
| 👻 占位符标签 | 输入框只有 placeholder，没有 label | 始终在输入框上方添加可见的 `<label>` |
| ⏳ 缺失加载状态 | 点击按钮后 2 秒没反应 | 超过 300ms 的操作都需要视觉反馈 |
| 🍞 弹窗式错误 | 错误只用 toast 显示，3 秒后消失 | 在相关字段旁显示内联错误，持续到问题解决 |
| 🤖 机器人语言 | 「操作已成功完成。」「检测到无效输入。」 | 用人话写：「保存成功！」「请输入有效的邮箱地址。」 |
| 🔮 神秘图标 | 只有图标没有文字标签，用户靠猜 | 图标配文字标签，纯图标必须有 aria-label |
| 📱 桌面 UI 硬塞手机 | 横向表格、微小按钮、hover 交互 | 移动端重新设计：纵向堆叠、放大触摸目标 |
| 📐 巨标题配蚂蚁字 | H1 是 64px，正文只有 12px | 正文最小 16px（Web）/14px（移动），标题比例 1.25–1.5× |
| 📄 空白空状态 | 没有数据时显示空白页面 | 说明用途 + 提供操作入口 + 可选插图 |
| 🔄 布局抖动 | 图片/字体加载时内容跳动 | 预留图片空间（明确 width/height），使用 font-display:swap |
